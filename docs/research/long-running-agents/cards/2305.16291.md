# 2305.16291: Voyager: An Open-Ended Embodied Agent with Large Language Models

1. Problem and claim: (a) An agent should keep learning for hundreds of steps without fine-tuning. Claim: a task-proposing curriculum plus a growing library of verified code skills compounds abilities and avoids forgetting. (b) "Empirically, VOYAGER shows strong in-context lifelong learning capability and exhibits exceptional proficiency in playing Minecraft." (c) Abstract.

2. Mechanism: (a) Procedural memory is executable JavaScript. A skill is saved only after a GPT-4 critic says the task succeeded, keyed by the embedding of a GPT-3.5 description. The top 5 are read into the next prompt. Each LLM call is one system plus one user message, with no chat history. Nothing is deleted. The curriculum prompt carries state plus completed and failed task lists, with a warm-up schedule that adds fields as tasks complete. (b) "The key is the embedding vector of the program description (generated by GPT-3.5), while the value is the program itself." (c) Sec. 2.2, Fig. 4 caption; Sec. 2.1; Appendix A.2 and A.3.3.

3. Evidence: (a) 63 unique items in 160 iterations, 3.3x baselines; tech levels 6.4x to 15.3x faster; in a new world all 4 unseen tasks solved (3/3 runs), baselines 0. Random curriculum cut items 93%; no self-verification cut 73%. (b) "discovering 63 unique items within 160 prompting iterations, 3.3× many novel items compared to its counterparts" (c) Sec. 3.3, Tables 1-2, Sec. 3.4.

4. Limits: (a) GPT-4 costs 15x GPT-3.5. The agent sometimes gets stuck. The critic can miss successes. The curriculum proposes impossible tasks, and code calls missing functions. (b) "The automatic curriculum occasionally proposes unachievable tasks." (c) Sec. 4.

5. (inferred) Ideas for Goals:
   - Recipe files: save a reusable recipe (steps, commands, check) only after proof passes, with a one-line description on top; a hook loads the best few matches into context.
   - Fresh-context verifier: returns pass or fail plus a critique, written to the proof file before anything is marked done.
   - Task ledger: plain lists of completed and failed tasks; failed ones are retried later and removed when done.
   - Rebuild a small prompt from files each round, so a full window never matters.
   - Add a prune or version rule, since Voyager never forgets.

7. Where the logic lives:

   - voyager/agents/critic.py: self-verification, returns success and critique.
   - voyager/agents/action.py: action prompt, chest memory, chat log summary.

10. Paper vs code: Retrieval matches the paper (task advice plus chat log as query, top 5). The code adds details the main text omits. The first task is hard-coded to mine one wood log. A chest-deposit task is forced when the inventory is nearly full, and it is never saved as a skill. Each prompt field is randomly dropped 20% of the time after warm-up. A question-answer cache dedupes by vector distance. A rewritten skill replaces its index entry, and only the file name gets a V2 suffix. A failed task leaves the failed list once it later succeeds. All skill code is loaded into the game, but only 5 appear in the prompt. Neither paper nor code prunes skills.
