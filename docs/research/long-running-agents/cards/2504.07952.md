# 2504.07952: Dynamic Cheatsheet: Test-Time Learning with Adaptive Memory

## Paper
1. Problem and claim: (a) A deployed model forgets every past query and repeats mistakes. Claim: a small curated text memory, rewritten after each query with no labels or weight updates, lets a black-box model improve over a task stream. (b) "typically retain no explicit or implicit memory of past questions, successes, or mistakes during inference" (c) Section 1, page 2.
2. Mechanism: (a) One text document of tagged entries (strategies, code, examples, usage counts). The generator reads it with each query; after each answer a curator prompt rewrites the whole sheet. DC-RS also retrieves top-3 similar past pairs first. (b) "it has to assess the correctness and efficiency of the solutions by itself before updating the memory" (c) Section 2.1.2, page 3.
3. Evidence: (a) GPT-4o on Game of 24 went from 10% to 99% (DC-RS) after storing a Python solver. Claude 3.5 Sonnet on AIME 2024 went from 23.3% to 50.0% (DC-Cu). Full history scored 26.7%. (b) "Under DC-RS, its performance increased to 99%" (c) Section 4.1, page 5, Table 1.
4. Limits the authors admit: (a) Needs a strong base model; weak models fill memory with flawed entries that get amplified. Rewrites can be truncated, retrieval can confuse, and updates are sequential. (b) "DC can amplify the strengths of models that can already produce high-quality outputs, but not fix foundational gaps in reasoning." (c) Section 1, page 2 (also Section 5, page 9).
5. (inferred) What Goals could take:
   - One short `lessons.md` per goal in the paper's entry shape: description, example, usage count, source phase. A curator prompt rewrites it at each phase end.
   - A hook injects it at phase start. Cap near 2,000 words.
   - A write-guard hook rejects a rewrite that shrinks the file sharply or contains "[...] preserved", and keeps the old version.
   - The paper's curator has no ground truth. Goals has proof files, so add an entry only when a passing proof backs it, and store the proof path in the entry.
   - A hook bumps an entry's count when a phase cites it, and prunes the lowest counts over the cap.
   - Retrieval can be plain keyword search over past phase records.

Repo: https://github.com/suzgunmirac/dynamic-cheatsheet
6. Repo facts: MIT license (LICENSE). Python. Folders: dynamic_cheatsheet, text_generation, prompts, data, embeddings, results, figures. README presents both the paper's benchmark runs (run_benchmark.py) and a usable library (LanguageModel.advanced_generate).
7. Where the logic lives:
   - dynamic_cheatsheet/language_model.py: advanced_generate with all six approaches.
   - dynamic_cheatsheet/utils/extractor.py: pulls the new sheet from the curator reply, falls back to the old one.
   - run_benchmark.py: loop carrying the sheet across queries, writes JSONL, can resume.
   - prompts/curator_prompt_for_dc_cumulative.txt and prompts/curator_prompt_for_dc_retrieval_synthesis.txt: curator rules.
   - prompts/generator_prompt.txt: how the solver uses the sheet.
8. Storage: the memory is a plain string in `<cheatsheet>` / `<memory_item>` tags, returned as `final_cheatsheet`; each step is saved as a JSONL line; embeddings are precomputed CSVs.

9. Prompts and policies: the curator must copy forward what it keeps, keeps usage counts, and discards trivia. The size limit is only in the prompt.
   [prompts/curator_prompt_for_dc_cumulative.txt:62] <<- Use the count to prioritize frequently used solutions over rarely applied ones.>>
   [prompts/curator_prompt_for_dc_cumulative.txt:128] <<N.B. Make sure that all information related to the cheatsheet is wrapped inside the <cheatsheet> block. The cheatsheet can be as long as circa 2000-2500 words.>>
   [prompts/curator_prompt_for_dc_retrieval_synthesis.txt:15] <<- Discard redundant, trivial, or highly problem-specific details that do not generalize well.>>
10. Paper vs code: the code adds a hybrid CumulativeRetrieval mode and a multi-round option (max_num_rounds, default 1) the paper text does not describe. The paper uses text-embedding-3-small, but the repo only loads precomputed CSVs and has no embedding code. Usage counting, pruning and size limits exist only as prompt text; no code checks for truncated rewrites. A curator reply without a `<cheatsheet>` tag silently keeps the old sheet.
