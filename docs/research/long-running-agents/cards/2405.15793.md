# 2405.15793: SWE-agent: Agent-Computer Interfaces Enable Automated Software Engineering

## Paper

1. Problem and claim: A raw Linux shell floods the model with output and gives no feedback on bad edits, so multi-step coding runs drift. Claim: a purpose-built interface (compact commands, short feedback, trimmed history, guardrails) lifts a fixed model.
   Quote: "manage history to avoid unnecessary context from prior observations"
   Where: Section 2 (ACI design principles), page 3.

2. Mechanism: Nothing is learned across runs. Each step rebuilds the history: old observations shrink to one line, only recent ones stay. A linter in the edit command rejects bad edits and shows before/after. Malformed output triggers a retry message.
   Quote: "observations preceding the last 5 are each collapsed into a single line"
   Where: Section 3, Context management, page 4.

3. Evidence: GPT-4 Turbo resolves 12.47% of full SWE-bench (286/2,294) and 18.0% of Lite. Lite ablations: full history 15.0, no linting 15.0, no edit command 10.3. Edit recovery: 90.5% at first, 57.2% after one failure.
   Quote: "SWE-agent solves 12.47% of the 2,294 SWE-bench test tasks"
   Where: Section 1 (Introduction), page 2; Table 3 and Section 5.2.

4. Limits: The interface was tuned by hand from reading trajectories. Scope is programming tasks only. Authors name automating ACI design, and keeping gains over a longer horizon, as open questions.
   Quote: "the ACI development process and case studies are done manually"
   Where: Appendix E.3 Limitations and Future Work, page 117.

5. (inferred) What Goals could take:
   - Output stubs: a hook saves long tool output to `.goals/evidence/step-N.txt` and returns a one-line stub plus the path. Never stub the goal and plan text (the code keeps the first observation).
   - State header: re-print a tiny state block (phase, open decisions, diff stat) each turn, like SWE-agent's state command.
   - Edit guard: a PreToolUse hook lints edits and rejects with before/after plus 'do not re-run the same command'. After 2 failed edits, require a note in the decisions file.
   - Two-step done: first "phase done" returns a checklist and the diff; the second confirms.
   - Exit save: on cost or context exit, write diff and status to disk.
   - Step budget: failures ran longer than successes; flag a re-plan when steps pass the median with no new proof.

## Code

Repo: https://github.com/SWE-agent/SWE-agent

6. Repo facts: MIT license. Python. Folders: `sweagent/`, `tools/`, `config/`, `tests/`, `docs/`, `trajectories/`, `assets/`. README presents a usable agent framework (CLI, YAML config) and points to mini-swe-agent as successor. The paper's setup survives as `config/sweagent_0_7/07.yaml`.

7. Where the logic lives:
   - `sweagent/agent/history_processors.py`: history shrinking (last N observations, closed windows, regex removal).
   - `sweagent/agent/agents.py`: step loop, history store, requery on errors, autosubmit, RetryAgent.
   - `tools/windowed_edit_linting/bin/edit`: edit with flake8 check and revert.
   - `tools/review_on_submit_m/bin/submit`: staged review before final submit.
   - `tools/windowed/bin/_state`: per-step state file.

8. How it is stored: One in-memory list of message dicts, a trajectory list saved to disk, and JSON state files inside the sandbox.

   Requeries are capped by `max_requeries` (default 3), then the run exits and autosubmits.

10. Paper vs code:
   - The default history processor does nothing; `default.yaml` only sets prompt caching. Elision is opt-in via `last_n_observations`, whose docstring says current models often do not need it.
   - Paper: past errors except the first are dropped. As read, code keeps none in history (only in the saved trajectory).
   - Code adds what the paper does not describe: RetryAgent with `hard_reset` per attempt plus chooser or reviewer, closed-window processor, review-on-submit, cost/time/timeout exits with autosubmit.
   - Neither has cross-run memory; attempts start fresh.
