# 2510.04618: Agentic Context Engineering: Evolving Contexts for Self-Improving Language Models

## Paper

1. Problem and claim: When an LLM rewrites the agent's whole notes each step, they shrink and lose detail (context collapse, brevity bias). Claim: keep context as an itemized playbook edited by small deltas, and it keeps improving.
   - Quote: "context collapse: methods that rely on monolithic rewriting by an LLM often degrade into shorter, less informative summaries over time, causing sharp performance declines"
   - Where: Section 1, Introduction.

2. Mechanism: Context is a list of bullets, each with an id, helpful and harmful counters, and one small piece of text. The Generator marks bullets it used, the Reflector critiques, the Curator proposes new bullets only, and code merges them. Duplicates are pruned by embedding similarity, eagerly or lazily.
   - Quote: "bullets with new identifiers are appended, while existing bullets are updated in place (e.g., incrementing counters)"
   - Where: Section 3.2, Grow-and-Refine (also 3.1).

3. Evidence: AppWorld average 42.4 (ReAct) rises to 59.4 offline and 59.5 online without labels; FiNER 70.7 to 78.3; Formula 67.5 to 85.5. Latency is 82.3% lower than GEPA. Without incremental updates, test-normal average falls from 70.3 to 56.9.
   - Quote: "consistently outperforming strong baselines: +10.6% on agents and +8.6% on finance, while significantly reducing adaptation latency and rollout cost"
   - Where: Abstract; Tables 1, 2, 4, 18.

4. Limits: Needs a reasonably strong Reflector and reliable feedback (labels or execution results); otherwise the playbook gets polluted and accuracy falls. Short-context tasks (HotPotQA, Game of 24) gain little.
   - Quote: "A limitation of ACE is its reliance on a reasonably strong Reflector"
   - Where: Section 5, Limitations and Challenges (also 4.4).

5. (inferred) What Goals could take:
   - Keep `playbook.md` as one-line bullets (`[id] helpful=N harmful=M :: text`) under section headings. A hook appends bullets and bumps counters in code; the model never rewrites the file.
   - After each phase, a reflect prompt reads the proof and the cited bullets, returns tags and a few new bullets.
   - Log cited bullet ids in the proof file so counters reflect real use.
   - A size-check hook flags the file past a token cap and requests a reviewed merge pass.
   - Reflect only on solid signals (tests, exit codes).

7. Where the logic lives:
   - `ace/ace.py`: orchestrator loop (generate, reflect, curate) and the empty seven-section playbook.
   - `ace/core/generator.py`, `ace/core/reflector.py`: the roles; generator returns the bullet ids it used.
   - `ace/core/curator.py`: asks for JSON operations, validates, applies them.
   - `playbook_utils.py`: parse bullets, update counters, apply ADD, stats.
   - `ace/core/bulletpoint_analyzer.py`: optional embedding dedup with LLM merge.

9. Prompts and policies: the Reflector tags each used bullet; the Curator may only add.
