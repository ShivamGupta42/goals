# 2509.25140: ReasoningBank: Scaling Agent Self-Evolving with Reasoning Memory

## Paper

1. Problem and claim.
   (a) Agents facing a stream of tasks discard past experience and repeat mistakes. Claim: strategy-level memory distilled from self-judged successes and failures, plus memory-aware test-time scaling, improves the agent over time without labels.
   (b) "A key limitation, however, is their failure to learn from the accumulated interaction history, forcing them to discard valuable insights and repeat past errors."
   (c) Abstract, p. 1.

2. Mechanism.
   (a) Text items {title, description, content}, at most 3 per trajectory, written by an LLM after each task from a judged success or failure. Top-k (default 1) similar past queries, found by embedding, go into the system prompt. Append-only, no forgetting.
   (b) "newly generated items are directly added without additional pruning."
   (c) Appendix A.2, Memory Consolidation, p. 23.

3. Evidence.
   (a) WebArena overall success, Gemini-2.5-flash: 40.5 no memory, 48.8 ReasoningBank, 51.8 with MaTTS (k=5); steps 9.7 to 8.3. SWE-Bench-Verified flash 34.2 to 38.8, pro 54.0 to 57.4.
   (b) "improves the overall success rate on WebArena (Table 1) by +8.3, +7.2, and +4.6 with three different backbone LLMs compared to memory-free agents."
   (c) Section 4.2, p. 7 (Tables 1 and 2).

4. Limits the authors admit.
   (a) Retrieval and consolidation are deliberately simple. Success labels come from an LLM judge (72.7% accurate in their test) that may be noisy. Other memory architectures were not compared.
   (b) "it may introduce noise when tasks are ambiguous or when the judge model itself errs."
   (c) Appendix E, Limitations, p. 30.

5. (inferred) What Goals could take from it.
   - A plain `lessons.md`: one block per item with Title, 'use when / do NOT use when', 1-3 sentence Content. Cap 3 new items per phase.
   - Phase-end hook: the model writes lessons from passed and failed phases, using the proof file as the success signal instead of an LLM judge.
   - Phase-start hook: grep the lessons, inject the top 1-3 into the prompt with 'say whether you use each item, then act'.
   - The paper never forgets, so add last-used date, hit count, a retire flag and a dedupe check at write time.
   - When a phase is stuck, run 2-3 attempts and write one lesson contrasting them (parallel MaTTS).

## Code

Repo: https://github.com/google-research/reasoning-bank

6. Repo facts: Apache-2.0 LICENSE; Python; folders WebArena/, SWE-Bench/, third_party/ (vendored webarena fixes, mini-swe-agent copy with a memory package), assets/. README says it releases SWE-Bench and WebArena experiment code and is a demonstration, not for production. Experiments only, not a library.

7. Where the logic lives:
   - WebArena/pipeline_memory.py: per-task loop of run, judge, extract.
   - WebArena/induce_memory.py: judged trajectory to memory items, appended to JSONL.
   - WebArena/memory_management.py: embedding cache and cosine retrieval.
   - WebArena/run.py: retrieves before the run; agents/legacy/agent.py adds items to the system message.
   - WebArena/prompts/memory_instruction.py: extraction and scaling prompts.
   - third_party/src/minisweagent/run/extra/swebench.py: same loop for SWE-Bench.

8. Storage: one JSONL per website (task_id, query, think/action lists, status, memory_items, template_id) plus a JSONL cache of 3072-dim query embeddings.
   - [WebArena/induce_memory.py:184] <<"memory_items": generated_memory_item.split("\n\n"),>>
   - [WebArena/memory_management.py:211] <<scores = (instruct_vec @ cache_emb.T).squeeze(0) * 100.0  # (N,)>>
   - [WebArena/run.py:177] <<res = select_memory(n=1,>>

9. Prompts and policies: separate success and failure extraction prompts (at most 3 items, no site-specific strings); the judge's reasoning is appended before extraction.
   - [WebArena/prompts/memory_instruction.py:24] <<- You can extract *at most 3* memory items from the trajectory.>>
   - [WebArena/induce_memory.py:162] <<trajectory += f"\n\nThe task {status_label} because: {autoeval_thoughts}">>

10. Paper vs code:
   - Sequential-scaling prompts exist but nothing calls them; no best-of-N selection; no Mind2Web.
   - Parallel scaling looks broken: it reads one result folder num_samples times, and labels reward 0 as success: [WebArena/induce_scaling.py:181] <<if reward == 0:>>
   - The judge is the repo's autoeval, not the paper's Figure 10 prompt. Retrieval returns all items of the one closest past task. No pruning or merging, as the paper says.
