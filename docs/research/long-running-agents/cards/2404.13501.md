# 2404.13501: A Survey on the Memory Mechanism of Large Language Model based Agents

1. Problem and claim: Agents need memory for long-term, complex interactions, but designs are scattered. The survey is a review that gives taxonomies and principles for designing and evaluating agent memory.
   - Quote: "present clear taxonomies and key principles for designing and evaluating the memory module" (Section 1, Introduction)

2. Mechanism: Its taxonomy: sources (inside-trial, cross-trial, external knowledge); forms (textual, or parametric = weights); operations: write, manage (merge, reflect, forget), read (similarity, top-K). Short-term within a trial, long-term across trials. Written each step, read before each action.
   - Quote: "project the raw observations into the actually stored memory contents" (Section 3.4, Memory Writing)

3. Evidence: No experiments of its own. Tables 1-3 tally 28 agent systems by source, form and operation. Textual memory is the mainstream form. Authors report no benchmark numbers.
   - Quote: "Textual form is currently the mainstream method to represent the memory contents" (Section 5.2.1, Memory in Textual Form)

4. Limits: Long textual histories cost compute and lose information. Parametric memory is under-researched and slow to build. No open benchmark exists for memory modules. Lifelong memory raises overlap between memories and a vast store to search.
   - Quote: "the fast-growing long-context memory in practice results in high computational cost during LLM" (Section 5.2.1, Complete Interactions)

5. (inferred) What a harness like Goals could take from it:
   - Write: a hook appends one line per step (action, result, source tag) to a run log. This is the paper's inside-trial store.
   - Manage: at phase end, a prompt writes lessons.md with failed tries and their causes. Mark old entries superseded instead of deleting them, so dates stay visible.
   - Read: a prompt-submit hook injects only the few matching lines from lessons.md and the decision file, not the whole log. The paper warns that recency alone neglects earlier critical information.
   - Keep sources in separate files (run log, lessons, external docs) so each claim shows where it came from.
   - Cap injected memory per turn. The paper says long prompts cost compute and that text position changes how well it is used, so test the cap against one known decision.
