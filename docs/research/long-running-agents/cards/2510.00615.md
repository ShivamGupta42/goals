# 2510.00615: ACON: Optimizing Context Compression for Long-horizon LLM Agents

## Paper

1. Problem and claim: Agent context grows without bound, raising memory cost and burying useful facts. Truncation and generic summaries drop ids, paths and state later steps need. Claim: learn the compression prompt from failures, with no weight updates.
   - Quote: "ACON employs an optimization in natural language space: it iteratively refines compression guidelines based on failure analysis of the agent"
   - Where: Abstract.

2. Mechanism: A natural-language compression prompt (the guideline) is rewritten by an optimizer LLM. Step UT: contrast no-compression successes with compressed failures, aggregate feedback, update, pick the best of 5. Step CO: from compressed successes, trim unused information.
   - Quote: "Such trajectory-level comparisons yield richer feedback than scalar rewards"
   - Where: Section 3.3.

3. Evidence: AppWorld gpt-4.1 history compression: UTCO 56.5 accuracy vs 56.0 uncompressed, peak 7.33k vs 9.93k tokens; plain prompting 43.5. Peak tokens down 26-54%; distilled compressors keep 95%; Qwen3-14B agent 25.6 to 33.9.
   - Quote: "ACON reduces peak tokens by over 25% while preserving the accuracy of the no compression upper bound"
   - Where: Section 4.2, Table 1.

4. Limits: Mostly GPT models; benchmarks only; no convergence guarantee for the text optimization; distilled models trail the teacher; compression adds latency.
   - Quote: "this approach lacks a formal convergence guarantee"
   - Where: Appendix A, Limitations and Future Works.

5. (inferred) What Goals could take:
   - Keep `compression_guideline.md` as the prompt that writes the handoff summary at a context reset, starting from ACON's headings: REASONING, VARS, TODO, COMPLETED, GUARDRAILS.
   - Kept: ids, paths, tokens, defaults, next steps, error lessons. Dropped: tool logs, repetition, chatter, expired credentials. Keep the last raw turn; replace the summary, never accumulate.
   - Failure loop: when a post-reset session loses or re-discovers a fact, a hook appends a line to `compression_failures.md`. After a few, a prompt proposes a guideline diff the user approves.
   - Failure-only analysis (no twin run) costs just 0.6 points in Table 3.
   - A tool-output hook compresses results over about 1k tokens but saves the raw output to a linked file, so dropping is reversible.

## Code

Repo: https://github.com/microsoft/acon

6. Repo facts: MIT LICENSE; Python 3.11+; folders `assets/`, `configs/`, `experiments/`, `src/`. README: official implementation of the paper, a research framework for compression and distillation pipelines. Experiments plus an installable package.

7. Where the logic lives:
   - `src/productive_agents/agents/memory.py`: triggers compression, starts a new session with the summary, keeps the last k turns.
   - `src/productive_agents/ctxopt/history_optimizer.py`: history compressor with token-threshold check.
   - `src/productive_agents/ctxopt/obs_optimizer.py`: observation compressor.
   - `experiments/prompt_optimizer/unified_update_history_prompt.py`: UT step; finds baseline-success, compressed-fail tasks, writes candidate prompts.
   - `experiments/prompt_optimizer/unified_compress_update_history_prompt.py`: CO step on compressed successes.
   - `experiments/appworld/run_ctxopt_pipeline.py`: runs candidates, picks the best.

8. How it is stored: sessions are lists of chat messages in memory; the summary is one string injected into the first user message. Guidelines are Jinja files on disk; analyses are JSON.

9. Prompts and policies: the analyst names root causes per failed task (missing fact, lost variable, summary error); these feed a prompt that rewrites the guideline. The CO analyst returns keep and remove_or_shorten lists (repetition, chatter, tool-logs, formatting, meta). Compression fires only above a token threshold (4096 for history).
   - [experiments/prompt_optimizer/prompts/history_regression_prompt.jinja:3] <<Analyze why the HISTORY-OPTIMIZED agent failed OR became significantly less efficient while the BASELINE succeeded.>>
   - [experiments/prompt_optimizer/prompts/history_context_reducer_analysis_prompt.jinja:4] <<Focus on CONTENT in the OUTPUT_SUMMARY, not the formatting. Identify which information can be dropped or compressed considering its impact on the next session.>>
   - [src/productive_agents/ctxopt/history_optimizer.py:161] <<return n_tokens > self.history_summarization_threshold>>

10. Paper vs code: Algorithm 1 is one automated UT then CO loop with reward-minus-cost selection. The code has separate scripts and no cost term; the pipeline picks the highest task completion, ties by fewest tokens, on a 38-task split. The CO script is undocumented. A code TODO admits summaries can accumulate; configs use "reset".
