# 2512.24601: Recursive Language Models

1. Problem and claim: (a) Long prompts and long agent histories overflow the window and degrade; compaction forgets details. Claim: keep the prompt outside the model, as a variable in a code environment, and let the model call itself on slices of it. (b) "arbitrarily long user prompts should not be fed into the neural network (e.g., Transformer) directly" (c) Section 1 Introduction, p.2.

2. Mechanism: (a) The prompt is a string variable in a persistent Python REPL. The root sees only metadata and truncated printed output. It writes code that loops sub-LM calls over slices, stores results in variables, and sets Final to finish. (b) "invokes the root neural model M with only (constant-size) metadata about the user prompt" (c) Section 2, Algorithm 1 text, p.3.

3. Evidence: (a) GPT-5 OOLONG 44.0 to 56.0 (RLM depth 1); OOLONG-Pairs F1 0.1 to 58.0; BrowseComp+ (6M-11M tokens) 91.3 vs compaction 70.5. RLM-Qwen3-8B beats Qwen3-8B by a median 28%. (b) "RLM(GPT-5, depth=1) has an average cost of $0.99 and outperforms both the compaction and retrieval baselines by over 29%" (c) Section 4, Observation 1, p.6; Table 1.

4. Limits the authors admit: (a) Sub-call costs can explode; guardrails are under-explored; sequential calls are slow; the FINAL tag is brittle; weak coders and small output budgets fail; prompts need per-model tuning. (b) "RLMs add a layer of complexity on top of existing LMs that may lead to unintentional side-effects like exploding sub-call costs" (c) Section 7 Limitations, p.9; Appendix B.

5. (inferred) What Goals could take:
- Keep big artifacts (logs, transcripts) as files, not prompt text. A session-start hook injects only a manifest (path, size, first line) and the rule: grep or slice, print small samples.
- A post-tool hook caps tool output near 20K characters and saves the full output to a file.
- Recursion by helper: one fresh helper per slice, narrow brief, terse answer written to a file; the main session reads only those. Depth 1, capped count.
- Compaction should not delete: save the full trajectory to `history.md`; the next prompt points at it.
- Budget hook: turn counter, cost and time caps, forced best answer at the limit.

6. Repo facts: MIT license (LICENSE). Python. Folders: rlm, tests, examples, docs, training, visualizer. README: a usable inference library (`pip install rlms`) plus an RL training environment. No baseline or benchmark runners; only an OOLONG training environment.

7. Where the logic lives:
- rlm/core/rlm.py: turn loop, depth cap, child-RLM spawn, compaction, limits.
- rlm/environments/local_repl.py: persistent REPL namespace; context variable; llm_query and rlm_query; `answer` dict.
- rlm/utils/prompts.py: system prompt, orchestrator addendum, per-turn prompt.
- rlm/utils/parsing.py: extracts repl blocks; truncates REPL output for history.
- rlm/core/types.py: QueryMetadata (context type and lengths for the root).

8. How it is stored: context goes to a temp file, then into variable `context_0` (alias `context`). The REPL namespace is one dict kept across turns. Compaction keeps a list; persistent mode keeps `history_N`.

10. Paper vs code:
- Paper ends with FINAL() or FINAL_VAR(); code ends when the REPL sets `answer["ready"] = True`.
- Paper: a short stdout prefix reaches history; code: up to 20,000 characters.
- Paper's sub-calls are sequential; code adds batched thread-pool calls.
- Code splits `llm_query` (plain call) from `rlm_query` (child RLM, own REPL).
- Code adds summary compaction, persistent multi-turn contexts, and budget, timeout and error limits; the paper has compaction only as a baseline.
