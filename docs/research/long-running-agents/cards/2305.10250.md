# 2305.10250: MemoryBank: Enhancing Large Language Models with Long-Term Memory

## Paper

1. Problem and claim.
   (a) LLMs forget everything between sessions, which hurts companions and counselors. MemoryBank adds external memory: retrieval, daily and global summaries, a user portrait, and Ebbinghaus forgetting with reinforcement.
   (b) "Long-term memory in AI is vital to maintain contextual understanding, ensure meaningful interactions and understand user behaviors over time."
   (c) Section 1, Introduction.

2. Mechanism.
   (a) Text store: timestamped dialog turns, LLM daily event summaries rolled into a global summary, daily then global personality notes. Items are embedded (FAISS) and retrieved by the current message. Each has strength S, start 1; retention R = e^(-t/S). On recall S rises by 1 and t resets; unrecalled items fade.
   (b) "We increase S by 1 and reset t to 0, hence forget it with a lower probability."
   (c) Section 2.3, Memory Updating Mechanism.

3. Evidence.
   (a) 15 simulated users, 10 days, 194 probing questions, human-scored. ChatGPT variant, English: retrieval 0.763, correctness 0.716, coherence 0.912. ChatGLM and BELLE retrieve better but answer worse. Forgetting is not tested.
   (b) "Our overall best variant SiliconFriend ChatGPT has high performance across all metrics, showing the effectiveness of our overall framework."
   (c) Section 4.2, Result Analysis and Table 2.

4. Limits the authors admit.
   (a) No limitations section. The forgetting model is called exploratory and highly simplified (one discrete strength number); real memory is more complex.
   (b) "The forgetting curve will look different for different people and different types of information."
   (c) Section 2.3.

5. (inferred) What Goals could take.
   - Plain-file memory ledger: each note, decision or proof has created, last_used, strength. A SessionStart hook computes retention and loads only entries above a threshold. Use a fixed cutoff, not a random draw; move faded entries to an archive file, never delete. Pin the plan.
   - Reinforce on real use: a Stop hook bumps strength only for entries cited that turn.
   - Hierarchical summaries: a PreCompact or Stop hook writes a per-session summary file, then one rolling overall summary. After a reset, inject that plus a few retrieved entries.
   - Fix the formula bug below before copying.

## Code

6. Repo facts. MIT license. Python. Folders: SiliconFriend-ChatGLM-BELLE, SiliconFriend-ChatGPT, memory_bank, utils, eval_data, resources. README: data, model and code for the paper's demos and experiments, not a packaged library.

7. Where the logic lives.
   - memory_bank/memory_retrieval/forget_memory.py: forgetting curve, strength bump, load-time forgetting, retrieval.
   - memory_bank/memory_retrieval/local_doc_qa.py: same retrieval without forgetting (default).

   - utils/prompt_utils.py: meta prompts inserting retrieved memory and personality.
   - utils/sys_args.py: flags (forgetting off, top-k 2).

10. Paper vs code.
   - Formula bug: paper has e^(-t/S); code computes (-t/5)*S, so higher S forgets faster. Recall helps only by resetting t.
   - Forgetting is off by default [utils/sys_args.py:10] <<enable_forget_mechanism: bool = field(default=False)>>. It runs only at login. Summaries are never forgotten. The ChatGPT variant has none.
   - CLI imports a missing module [SiliconFriend-ChatGLM-BELLE/cli_demo.py:53] <<from memory_retrieval.forget_memory_new import LocalMemoryRetrieval>>.
   - Paper puts the global summary in the prompt; templates have no history_summary placeholder, so it is built but never shown (grep).
   - Likely bug (read only): cli_demo.py loads the JSON before forgetting runs, then rewrites that stale dict each turn, probably erasing strength updates.
   - Context handling: only the last 7 turns are kept.
