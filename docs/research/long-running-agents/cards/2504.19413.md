# 2504.19413: Mem0: Building Production-Ready AI Agents with Scalable Long-Term Memory

## Paper

1. Problem and claim
- (a) Fixed context windows break consistency across long multi-session chats. Mem0 extracts, consolidates and retrieves salient facts instead of replaying history, claiming better answers than other memory systems at far lower latency and token cost.
- (b) "their fixed context windows pose fundamental challenges for maintaining consistency over prolonged multi-session dialogues"
- (c) Abstract

2. Mechanism
- (a) Natural-language facts in a vector store (Mem0g: Neo4j triplets). An LLM extracts facts from each new message pair with summary context; each fact is checked against top 10 similar memories, and the LLM picks ADD, UPDATE, DELETE or NOOP.
- (b) "The LLM itself determines which of four distinct operations to execute: ADD for creation of new memories when no semantically equivalent memory exists"
- (c) Section 2.1 (Mem0), page 4; Algorithm 1, Appendix B

3. Evidence
- (a) LOCOMO overall J: Mem0 66.88, Mem0g 68.44, full-context 72.90, OpenAI 52.90, best RAG about 61. Mem0 p95 total latency 1.44s vs 17.1s full-context; memory about 7k tokens vs 26k raw.
- (b) "Mem0 attains a 91% lower p95 latency and saves more than 90% token cost"
- (c) Abstract; Table 2

4. Limits the authors admit
- (a) No limitations section. Concedes full-context still scores higher. Future work lists graph latency, hierarchical memory and richer consolidation; only conversation tested, not procedural or multimodal.
- (b) "Future research directions include optimizing graph operations to reduce the latency overhead in Mem0g, exploring hierarchical memory architectures"
- (c) Section 5, Conclusion and Future Work

5. (inferred) What Goals could take
- A hook at turn end or before compaction runs an extraction prompt over the last 10 messages and appends facts to a plain `.goals/memory.jsonl` (id, text, absolute date).
- Show the model the 10 closest existing facts under short ids, found by grep.
- Append only: write `supersedes: <id>` instead of deleting, and keep a history file of old and new text.
- Run an md5 duplicate check in the hook script before asking the model.

## Code

Repo: https://github.com/mem0ai/mem0

README presents a usable library, self-hosted server and cloud platform; the paper's experiments are not here.

7. Where the logic lives:
- `mem0/memory/main.py`: add pipeline, update, delete, history.
- `mem0/configs/prompts.py`: legacy and current prompts, prompt builder.
- `mem0/memory/storage.py`: SQLite history and messages tables.
- `mem0/memory/utils.py`: parse_messages, legacy prompt selection.
- `mem0/utils/entity_extraction.py`: entity linking.

8. How it is stored:
- [mem0/memory/main.py:1032] <<mem_metadata["data"] = text>> each memory is a vector-store record: fact text in the payload, plus hash and timestamps.
- [mem0/memory/storage.py:108] <<CREATE TABLE IF NOT EXISTS history (>> audit rows: old_memory, new_memory, event.
- [mem0/memory/storage.py:284] <<DELETE FROM messages WHERE session_scope = ? AND id NOT IN (>> keeps the latest 10 raw messages per session.

9. Prompts and policies:
- [mem0/configs/prompts.py:184] <<- DELETE: Delete an existing memory element>> legacy update prompt: ADD, UPDATE, DELETE, NONE.
- [mem0/configs/prompts.py:699] <<- **Contradiction**: New information that conflicts with an existing memory>> current prompt is ADD-only; conflicts become links.
- [mem0/memory/main.py:1023] <<if mem_hash in existing_hashes or mem_hash in seen_hashes:>> md5 duplicate check replaces the LLM NOOP.

10. Paper vs code:
- The four-operation tool call is legacy: `DEFAULT_UPDATE_MEMORY_PROMPT` stays in prompts.py but main.py never imports it. add() is one ADD-only LLM call; UPDATE and DELETE happen only via explicit update() and delete() calls.
- The LLM may emit `linked_memory_ids`, but the add path keeps only text and attributed_to.
- The rolling summary is not generated; the code uses the last 10 raw messages and top 10 memories, matching the paper's m and s.
- Mem0g and Neo4j are removed from OSS.
- README scores (LoCoMo 92.5) are for a newer algorithm, not the paper's 66.88.
