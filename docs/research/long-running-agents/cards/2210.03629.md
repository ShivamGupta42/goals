# 2210.03629: ReAct: Synergizing Reasoning and Acting in Language Models

## Paper

1. **Problem and claim.** (a) Not a long-run memory paper. Models either reason (chain-of-thought) or act, not both. Claim: interleaving free-text thoughts with actions lets a frozen model plan, track progress, recover from errors and stay grounded. (b) "reasoning traces help the model induce, track, and update action plans as well as handle exceptions" (c) Abstract.

2. **Mechanism.** (a) No store outside the prompt. The frozen LLM writes a Thought (no effect on the world), then an Action; the environment returns an Observation. All three append to one growing prompt after 1 to 6 examples. No summary. (b) "we alternate the generation of thoughts and actions so that the task-solving trajectory consists of multiple thought-action-observation steps" (c) Section 2 (context ct is the trajectory).

3. **Evidence.** (a) HotpotQA EM 27.4 (CoT 29.4); FEVER 60.9 (CoT 56.3). ALFWorld best-of-6 success 71 vs Act 45, BUTLER 37. WebShop success 40.0 vs IL+RL 28.7. ReAct and CoT-SC mixes reach 35.1 (HotpotQA) and 64.6 (FEVER). (b) "ReAct outperforms imitation and reinforcement learning methods by an absolute success rate of 34% and 10% respectively" (c) Abstract; Tables 1, 3, 4.

4. **Limits the authors admit.** (a) Hard tasks need more examples than the window holds. ReAct sometimes loops on earlier thoughts and actions; uninformative search causes 23% of errors. Finetuning tested only briefly. (b) "which unfortunately can easily go beyond the input length limit of in-context learning" (c) Section 6 Conclusion; Section 3.3.

5. **(inferred) What Goals could take.**
   - Append-only trajectory file, one line per step (why, action, evidence), written by a post-tool hook.
   - ReAct's useful thoughts (split goal, mark subgoal done, pick next) become plan-file checkboxes, re-injected every turn.
   - ReAct has no overflow policy: pin plan, proof and decisions at the top; trim only old observations.
   - Loop-guard hook: if recent actions repeat, or a step cap passes with no new proof, force a re-plan or ask the user.
   - Let the user edit a thought or decision line and re-inject it (Figure 5).
   - Nothing carries between runs, so run-100 memory must come from elsewhere.

## Code

Repo: https://github.com/ysymyth/ReAct

6. **Repo facts.** MIT license. Python: two modules plus notebooks. Folders `data/`, `prompts/`; files `wikienv.py`, `wrappers.py`, `base_config.yaml`, four notebooks (HotpotQA, FEVER, ALFWorld, WebShop). README: GPT-3 prompting code to rerun the paper's experiments, not a library.

7. **Where the logic lives.**
   - `hotpotqa.ipynb` (`FEVER.ipynb` is the same loop): `webthink()` grows the prompt step by step.
   - `alfworld.ipynb`: `alfworld_run()` loop, up to 49 steps.
   - `WebShop.ipynb`: `webshop_run()` loop, 15 steps, truncates history.
   - `wikienv.py`: `WikiEnv` search, lookup, finish, think actions.
   - `wrappers.py`: `LoggingWrapper` trajectory log; `HistoryWrapper` (unused).
   - `prompts/*.json`: few-shot example trajectories.

8. **How it is stored.** Context is one Python string. Logs are lists of observations and actions, dumped to `trajs/<id>.json`.
   - [wrappers.py:222] <<self.traj["observations"].append(obs)>>
   - [wrappers.py:236] <<json.dump(self.trajs, f)>>
   - [hotpotqa.ipynb:105] <<"        prompt += step_str\n",>>

9. **Prompts and policies.** Fixed instruction plus examples; the step loop; a blunt character cut in WebShop.
   - [hotpotqa.ipynb:91] <<"    for i in range(1, 8):\n",>>
   - [hotpotqa.ipynb:83] <<"webthink_prompt = instruction + webthink_examples\n",>>
   - [WebShop.ipynb:364] <<"    action = llm(init_prompt + prompt[-(6400-len(init_prompt)):], stop=['\\n']).lstrip(' ')\n",>>

10. **Paper vs code.**
   - Code calls OpenAI text-davinci-002; PaLM-540B is not released.
   - Absent: CoT-SC and its fallbacks, finetuning, ReAct-IM, human thought editing.
   - Paper says FEVER stops at 5 steps; the FEVER notebook loops 7.
   - Paper uses 6 ALFWorld prompt permutations; the notebook uses one fixed pair.
   - Paper is silent on overflow; only WebShop truncates (last 6400 characters). The others use step caps (7, 49).
   - HotpotQA thoughts are parsed from text; `WikiEnv` has a `think[]` action nothing calls.
