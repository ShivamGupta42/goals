# 2506.06326: Memory OS of AI Agent

## Paper

1. **Problem and claim.** (a) Fixed context windows break continuity and personalization in long, multi-session chats. Claim: an OS-style three-tier memory (short, mid, long-term) with explicit update rules fixes this and beats MemGPT, A-Mem, TiM, MemoryBank. (b) "struggles to preserve continuity in dialogues with significant temporal gaps" (c) 1 Introduction.

2. **Mechanism.** (a) STM holds 7 recent pages; the oldest moves to MTM topic segments (match above 0.6). Segment heat = visits + pages + recency; coldest evicted, heat above 5 rewrites LPM profile and 100-entry fact queues. (b) "When the STM queue reaches its maximum capacity, the oldest dialogue page is transferred from the STM to the MTM" (c) 3.3 Memory Update Module.

3. **Evidence.** (a) LoCoMo, GPT-4o-mini: F1 35.27 / 41.15 / 20.02 / 48.62 (single, multi, temporal, open), measured against the authors' own A-Mem rerun. GVD accuracy 93.3 vs 90.4. 3,874 retrieval tokens vs MemGPT 16,977. (b) "Extensive experiments on the LoCoMo benchmark show an average improvement of 49.11% on F1 and 46.18% on BLEU-1 over the baselines on GPT-4o-mini" (c) Abstract; Tables 1-3.

4. **Limits the authors admit.** Not stated

5. **(inferred) What Goals could take.**
   - Three plain tiers: `recent.md` (last N turns), `topics/<slug>.md` (summary, keywords, visit count, last-read date), `profile.md` plus a capped `facts.md`. A Stop or PreCompact hook moves the oldest recent turn into the closest topic file, or starts a new one.
   - Promotion rule as a small hook script: heat = visits + entries + exp(-age/const). Past a threshold, run a prompt that rewrites `profile.md` from only the not-yet-analyzed entries, mark them analyzed, reset the counters (the paper's anti-repeat trick).
   - SessionStart hook injects profile, facts and the top-k topic entries; every read bumps that topic's visit count in the file.
   - Pin plan, proof and decisions so FIFO or lowest-use eviction never hits them; archive cold topics, do not delete.
   - A cheap true/false prompt decides same topic or new topic.

## Code

Repo: https://github.com/BAI-LAB/MemoryOS

6. **Repo facts.** LICENSE is Apache 2.0. Python. Folders: `memoryos-pypi`, `memoryos-playground`, `memoryos-mcp`, `memoryos-chromadb`, `eval`, `docs`. README presents both a usable library (PyPI, MCP server, ChromaDB) and a reproduce path via `eval/`.

7. **Where the logic lives.**
   - `memoryos-pypi/memoryos.py`: orchestrator; `add_memory`, `get_response`, heat-triggered LPM update.
   - `memoryos-pypi/short_term.py`: STM deque persisted to JSON.
   - `memoryos-pypi/updater.py`: STM to MTM; continuity check, chain meta summary, topic summaries, segment insert.
   - `memoryos-pypi/mid_term.py`: segments, heat, eviction, search.
   - `memoryos-pypi/long_term.py`: profile text plus fact queues.
   - `memoryos-pypi/prompts.py`: all prompts.

8. **How it is stored.** JSON files per user (`short_term.json`, `mid_term.json`, `long_term_user.json`) and per assistant (`long_term_assistant.json`); FAISS built in memory at search time.

10. **Paper vs code.**
   - Eviction: paper evicts the lowest-heat segment; code evicts by lowest access count (LFU). [memoryos-pypi/mid_term.py:75] <<lfu_sid = min(self.access_frequency, key=self.access_frequency.get)>>
   - Promotion: paper moves hot segments to LPM; code checks only the hottest segment per `add_memory`, leaves it in MTM, marks pages analyzed, zeroes visits. [memoryos-pypi/memoryos.py:211] <<session["N_visit"] = 0 # Reset visits after analysis>>
   - Defaults differ: paper STM 7, MTM 200, recency constant 1e7 seconds; library uses 10, 2000, 24 hours. The eval copy runs STM 1 and heat weights 0.8, 0.8, 0.0001. [eval/main_loco_parse.py:233] <<short_mem = ShortTermMemory(max_capacity=1, file_path=f"mem_tmp_loco_final/{sample_id}_short_term.json")>>
   - LPM: paper has 90 trait dimensions and static profile fields. Code keeps one free-text profile replaced wholesale, plus two fact queues.
   - `eval/` has LoCoMo scripts only; no GVD code.
