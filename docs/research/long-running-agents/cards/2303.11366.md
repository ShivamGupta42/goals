# 2303.11366: Reflexion: Language Agents with Verbal Reinforcement Learning

1. Problem and claim: (a) Agents that retry a task after failing must learn without weight updates. Claim: turning failure signals into written self-reflections, kept in memory and fed into the next attempt, improves later trials. (b) "Reflexion converts binary or scalar feedback from the environment into verbal feedback in the form of a textual summary" (c) Section 1 Introduction, p.2.

2. Mechanism: (a) Plain text only. Short-term: the current trajectory. Long-term: LLM-written reflections appended after each failed trial and put in the next Actor prompt. Forgetting: sliding window of the last 1-3 reflections. (b) "In the RL setup, the trajectory history serves as the short-term memory while outputs from the Self-Reflection model are stored in long-term memory." (c) Section 3, Memory paragraph, pp.4-5.

3. Evidence: (a) ALFWorld: 130 of 134 tasks solved. HumanEval Python pass@1 91% vs GPT-4 80%. HotPotQA +20%. Reflection beat last-trajectory-only memory by 8%. MBPP Python was lower (77.1 vs 80.1). (b) "ReAct + Reflexion significantly outperforms ReAct by completing 130 out of 134 tasks" (c) Section 4.1 ALFWorld Results, p.5.

4. Limits the authors admit: (a) Memory is only a fixed sliding window, no database. Can stall in local minima (WebShop showed no gain). Depends on LLM self-evaluation and good tests; no success guarantee. Weak models gain nothing (StarChat 0.26 to 0.26). (b) "we limit long-term memory to a sliding window with maximum capacity, but we encourage future work to extend the memory component of Reflexion" (c) Section 5 Limitations, p.9 (also App. A, B.1).

5. (inferred) What Goals could take:
- Keep `reflections.md` per goal. A hook appends a 2-5 sentence 'tried, why it failed, new plan' note only when a real check fails. A session-start hook injects the last 3 entries; older ones stay on disk.
- Stuck detector as a hook: same tool call twice in a row, or N steps with no new proof, forces a reflection step.
- Reflect only after a real failed check. Without unit tests the code ablation fell to 52% vs 60% baseline.
- Keep memory per goal, not global (ALFWorld memory is per environment). Promote repeated lessons to a shared decisions file after human review; the paper never transfers across tasks.
- Show old reflections to the reflector so new notes build on them.

7. Where the logic lives:
- alfworld_runs/generate_reflections.py: asks the LLM for a new plan after a failed trial; appends it to memory.
- alfworld_runs/env_history.py: builds the Actor prompt with the memory block; flags repeated actions.
- alfworld_runs/alfworld_trial.py: runs one trial, applies the 3-reflection window, skips solved environments.
- alfworld_runs/main.py: trial loop; saves env_results_trial_N.json.
- hotpotqa_runs/agents.py: ReactReflectAgent and CoTAgent reflection strategies.
- programming_runs/reflexion.py: test feedback, reflection, rewrite loop.

8. How it is stored:
- ALFWorld: a list of strings per environment, saved as JSON each trial. [alfworld_runs/main.py:51] <<'memory': [],>>
- [alfworld_runs/generate_reflections.py:45] <<env_configs[i]['memory'] += [reflection]>>
- HotPotQA: list on the agent object, joined into one prompt string. [hotpotqa_runs/agents.py:113] <<self.reflections += [self.prompt_reflection()]>>

9. Prompts and policies:
- Memory is shown to the Actor under a fixed heading. [alfworld_runs/env_history.py:48] <<query += '\n\nYour memory for the task below:'>>
- The reflector also sees past plans. [alfworld_runs/generate_reflections.py:22] <<query += '\n\nPlans from past attempts:\n'>>
- Forgetting rule: only the last 3 are read. [alfworld_runs/alfworld_trial.py:48] <<env_history = EnvironmentHistory(base_prompt, ob, memory[-3:], [])>>

10. Paper vs code:
- Paper: memory of 3 for HotPotQA. Code: no cap in hotpotqa_runs/agents.py. Only ALFWorld and WebShop slice [-3:].
- Paper: stuck means the same action and response for over 3 cycles, or over 30 actions. Code flags the second identical action in a row [alfworld_runs/env_history.py:18] <<if value == self._last_action:>> and caps at 49 steps [alfworld_runs/alfworld_trial.py:56] <<while cur_step < 49:>>.
- Paper Algorithm 1 shows one shared memory. Code keeps memory per environment and skips solved ones.
- Paper: code memory is 1 experience. Code keeps a reflections list but passes only the latest to the rewrite prompt.
- Vector or SQL memory (future work in the paper) is not in the code.
