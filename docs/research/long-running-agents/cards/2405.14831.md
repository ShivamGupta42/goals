# 2405.14831: HippoRAG: Neurobiologically Inspired Long-Term Memory for Large Language Models

1. Problem and claim: Standard RAG encodes each passage alone, so facts cannot be joined across passages. Claim: an LLM-built knowledge graph plus Personalized PageRank gives single-step multi-hop retrieval and cheap updates.
   - Quote: "inspired by the hippocampal indexing theory of human long-term memory to enable deeper and more efficient knowledge integration over new experiences"
   - Where: Abstract

2. Mechanism: Offline, an LLM extracts entities and triples per passage into a schemaless graph; synonym edges join nodes above cosine 0.8; a node-by-passage count matrix is kept. Online, query entities link to nodes, PPR runs from them (damping 0.5), and node scores are summed per passage. Rare nodes weigh more. New data only changes the index; no forgetting step.
   - Quote: "allows for new information to be integrated by changing only the hippocampal index instead of updating neocortical representations"
   - Where: Section 2.1

3. Evidence: Single-step HippoRAG beats other RAG methods on MuSiQue and 2Wiki (2Wiki R@5 89.1 vs ColBERTv2 68.2) and matches IRCoT at far lower online cost. Indexing costs about $15 per 10,000 passages.
   - Quote: "single-step HippoRAG is on par or outperforms IRCoT while being 10-30 times cheaper and 6-13 times faster during online retrieval"
   - Where: Section 4, Results (Appendix G)

4. Limits the authors admit: Components are untrained; most errors come from NER and OpenIE; large-scale behaviour is untested.
   - Quote: "we are yet to empirically prove the efficiency and efficacy of our synthetic hippocampal index as its size grows way beyond current benchmarks"
   - Where: Section 7, Conclusions and Limitations

5. (inferred) What Goals could take:
   - Write: a Stop hook turns each new decision or proof note into (entity, relation, entity) lines appended to a JSONL file, tagged with the note path. Never re-summarise old notes.
   - Read: at phase start, a hook extracts task entities, walks 1-2 hops over that file, and injects the top 3 note paths; rare entities weigh more.
   - Update: delete by note path, re-add.
   - Grep first; graph only when notes outgrow the window.

Repo: https://github.com/OSU-NLP-Group/HippoRAG

6. Repo facts: MIT license. Python. Folders: src, tests, reproduce, examples, plugins, outputs, images. The README is for HippoRAG 2 (the follow-up) and covers both a usable library (MCP server, Claude Code plugin) and experiment data; HippoRAG 1 is on a `legacy` branch, not here.

7. Where the logic lives:
   - src/hipporag/HippoRAG.py: indexing, graph build, delete, retrieve, PPR.
   - src/hipporag/embedding_store.py: parquet vector store for passages, entities, facts.
   - src/hipporag/rerank.py: LLM filter of facts.
   - src/hipporag/prompts/templates/triple_extraction.py: OpenIE prompt.
   - plugins/hipporag/skills/hipporag-memory/SKILL.md: when an agent reads or writes memory.

10. Paper vs code: the code is HippoRAG 2. Queries match whole facts, then an LLM filters them, instead of query NER to nodes. Passage nodes join the graph and rank by their own PPR score. Node specificity survives only as a fact-score division. Deletion, the manifest and MCP packaging are not in the paper.
