# 2310.08560: MemGPT: Towards LLMs as Operating Systems

## Paper

1. **Problem and claim.**
   (a) A fixed context window breaks long chats and long documents. Claim: treat the window like RAM and let the LLM page data to and from external storage with function calls.
   (b) "we study how to provide the illusion of an infinite context"
   (c) Section 1, Introduction.

2. **Mechanism.**
   (a) Main context = read-only system prompt + fixed-size working context (edited only by function call) + FIFO message queue headed by a recursive summary. External: recall storage (all messages), archival storage (text database). A warning near 70% full lets the model save facts; at 100% the queue is flushed and re-summarized.
   (b) "inserts a system message into the queue warning the LLM of an impending queue eviction"
   (c) Section 2.2, Queue Manager.

3. **Evidence.**
   (a) Deep memory retrieval accuracy with MemGPT: GPT-4 32.1% to 92.5%, GPT-4 Turbo 35.3% to 93.4%, GPT-3.5 38.7% to 66.9%.
   (b) "GPT-4 Turbo 35.3% 0.359 + MemGPT 93.4% 0.827"
   (c) Table 2, Section 3.1.1.

4. **Limits the authors admit.**
   (a) No limitations section. In results: GPT-3.5 does poorly because of weak function calling, and the agent often stops paging through search results early.
   (b) "MemGPT has significantly degraded performance using GPT-3.5, due to its limited function calling capabilities, and performs best using GPT-4."
   (c) Section 3.2.1, Multi-document question-answering.

5. **(inferred) What Goals could take from it.**
   - Pinned small file (plan, current step, open decisions) = working context, reloaded by a SessionStart hook. Append-only proof and decision logs = archival storage, searched with grep in capped pages.
   - Memory-pressure hook: past about 70% of the window, inject 'write decisions and proof to the files now'. A PreCompact hook does the same flush.
   - Recursive summary: each compaction prompt merges the old SUMMARY.md with evicted turns.
   - A Stop hook as heartbeat: continue while the goal's checks fail.
   - Caution: the model chooses what to save; nothing is pruned.

## Code

Repo: https://github.com/letta-ai/letta
Clone folder: letta-ai__letta-archive

6. **Repo facts.** This is the `archive` branch of letta-ai/letta: the retired Letta V1 server, a descendant of the 2023 MemGPT code and not necessarily identical to it (`main` is only a landing page). Apache 2.0 (LICENSE), Python (878 files), folders letta/, tests/, alembic/, db/, fern/, scripts/. README: the legacy Letta API server, a usable service, not the paper's experiments.

7. **Where the logic lives.**
   - letta/functions/function_sets/base.py: memory tool signatures the model sees.
   - letta/services/tool_executor/core_tool_executor.py: runs those tools.
   - letta/agent.py: step loop, memory-pressure flag, heartbeat chaining.
   - letta/services/summarizer/: eviction and summaries (summarizer_sliding_window.py, summarizer_config.py).
   - letta/prompts/system_prompts/memgpt_chat.py: memory-hierarchy prompt; letta/prompts/summarizer_prompt.py: summary prompts.

8. **How it is stored.** Core memory = labelled text blocks with a size limit, rendered into the system prompt. Archival = embedded passages (pgvector). Recall = the message table.
   [letta/schemas/block.py:20] <<limit: int = Field(CORE_MEMORY_BLOCK_CHAR_LIMIT, description="Character limit of the block.")>>
   [letta/orm/passage.py:79] <<__tablename__ = "archival_passages">>
   [letta/orm/message.py:26] <<__tablename__ = "messages">>

9. **Prompts and policies.** The system prompt teaches the memory tiers; warn threshold 0.75; the alert is sent once per period; summary prompts fold any earlier summary into the new one.

   [letta/settings.py:100] <<memory_warning_threshold: float = 0.75>>
   [letta/agent.py:969] <<# Only deliver the alert if we haven't already (this period)>>

10. **Paper vs code.**
    Found: main context (system prompt with core blocks, plus messages) vs external context (archival passages, message table); core_memory_append and core_memory_replace (base.py:263); archival_memory_insert and archival_memory_search; conversation_search; the memory-pressure warning (agent.py); summarization and eviction; request_heartbeat chaining.
    Differs: warning is off by default (settings.py:103 `send_memory_warning_message: bool = False`) and only the legacy agent.py sends it; compaction triggers at 0.9 of the window, not 100%; default mode sliding_window, 0.30 window percentage, not the paper's 50% eviction.
    Not in the paper: sleeptime background memory agents, memory_rethink and memory_insert tools, a git-backed memory repo.
    Not found: the paper's evaluation code (DMR, nested key-value, document QA).
