# 2508.16153: Memento: Fine-tuning LLM Agents without Fine-tuning LLMs

## Paper
1. Problem and claim: Agents should keep improving from experience without weight updates. Claim: cast planning as a memory-augmented MDP, store past cases in an episodic case bank, and learn which case to retrieve with online reinforcement learning while the LLM stays frozen.
   Quote: "our method enables low-cost continual adaptation via memory-based online reinforcement learning" (Abstract)

2. Mechanism: Each finished task appends a case (task, plan, success flag); the task is embedded by a frozen encoder. Reads take top-K by cosine similarity, or by a Q score trained online with cross-entropy on (task, case, success).
   Quote: "the Read operation of the parametric memory applies a TopK operator to select the K cases with the highest Q-values" (Section 4.2, Parametric Memory Retrieval)

3. Evidence: GAIA validation 87.88% Pass@3, test 79.40%. DeepResearcher 66.6 F1. Case memory adds 4.7-9.6 points out-of-distribution. Five iterations: no memory 78.65 to 84.47, parametric 80.46 to 85.44. K=4 retrieved cases is best.
   Quote: "case-based memory adds 4.7% to 9.6% absolute points on out-of-distribution tasks" (Abstract; Tables 3 and 4)

4. Limits the authors admit: No limitations section. Admitted: Level 3 GAIA tasks (long horizons, heavy tool use) remain hard; the case bank saturates quickly on about 3k tasks, so extra iterations give diminishing returns; probabilistic rewards and memory updates left for future work.
   Quote: "challenges remain for Level 3 tasks that require extended reasoning horizons and advanced tool coordination" (Section 5.4, GAIA)

5. (inferred) What Goals could take:
   - One case-bank JSONL file per goal. A hook at phase end appends {task, approach, proof verdict, proof path, why it failed}. Keep failures too.
   - At phase start a small script picks at most 4 cases (K=4 peaked), labels them worked or failed, and the prompt says follow the worked, avoid the failed.
   - No-training learned retrieval: log (task, case id, verdict) and rank by similarity times the case's win rate when retrieved.
   - Reward must be real: use the proof check; mark unproven cases "unverified", never "worked".
   - The paper never forgets; add retiring of low-win-rate cases. Measure first: the parametric gain shrank from 1.8 to 1.0 points by iteration 5 (Table 4).

## Code
Repo: https://github.com/Agent-on-the-Fly/Memento

6. Repo facts: MIT license. Python 3.11+. Folders: client, server, memory, data, searxng-docker, Figure. README presents runnable agent scripts and retriever training, not a library. README names files that are absent (retrain.sh, ckpts/, PARAMETRIC_MEMORY_GUIDE.md).

7. Memory logic files:
   - memory/np_memory.py: similarity read (SimCSE embed, cosine, top-K).
   - memory/parametric_memory.py: loads trained retriever, scores every pool case.
   - memory/train_memory_retriever.py: classifier model, offline training.
   - client/parametric_memory_cbr.py: agent loop, retrieval, prompt, judge, writes.
   - client/no_parametric_cbr.py: same loop, similarity retrieval.
   - memory/memory.jsonl, memory/training_data.jsonl: sample bank (1278 cases), 7000 pairs.

8. Stored as JSONL, one object per line. Bank line {case, plan, case_label}; similarity variant {question, plan, reward}; training pair {query, case, plan, case_label, truth_label}. Retriever: SimCSE backbone plus a small MLP over joined query and case vectors.

   [client/no_parametric_cbr.py:594] <<"reward": reward>>
   [memory/train_memory_retriever.py:15] <<class MemoryRetrieverClassifier(nn.Module):>>

9. Prompts and policies: retrieved cases are split into positive and negative examples inside the planner prompt. A case is positive if the LLM judge marked the answer correct. Every retrieved case gets the query's final verdict as its training label.
   [client/parametric_memory_cbr.py:160] <<"Focus on the positive examples and avoid the patterns shown in negative examples.\n\nYour plan:">>
   [client/parametric_memory_cbr.py:350] <<results.sort(key=lambda x: x["score"], reverse=True)>>
   [client/parametric_memory_cbr.py:508] <<"truth_label": is_correct>>

10. Paper vs code:
   - Paper updates Q online at every Write. Code appends cases and training pairs online, but the retriever changes only when train_memory_retriever.py is rerun by hand; no checkpoint or retrain script ships.
   - Soft Q-learning, entropy, TD targets and the kernel memory (Eq. 7-11) are absent; code is a binary classifier with top-K.
   - Default MEMORY_TOP_K is 8, not 4. Subtask and tool history are in-process lists cleared per query; the executor drops oldest messages past 175000 tokens.
