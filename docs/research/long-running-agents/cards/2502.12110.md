# 2502.12110: A-MEM: Agentic Memory for LLM Agents

## Paper

1. Problem and claim
(a) Agent memory uses fixed structures and fixed read/write points, so it adapts poorly. Claim: letting the LLM write, link and rewrite notes (Zettelkasten style) beats fixed memory on long-conversation QA at far fewer tokens.
(b) "These systems require agent developers to predefine memory storage structures, specify storage points within the workflow, and establish retrieval timing."
(c) Section 1 Introduction.

2. Mechanism
(a) Each interaction becomes a text note: content, timestamp, LLM-made keywords, tags, one-line context, links, plus one embedding. On write, top-k similar notes are fetched, the LLM picks links and may rewrite neighbours' context, keywords and tags. Read: plain top-k cosine search. No forgetting.
(b) "new memories automatically trigger two key operations: link generation and memory evolution."
(c) Section 1 Introduction; Sections 3.1 to 3.4.

3. Evidence
(a) LoCoMo, six models. GPT-4o-mini: about 2,520 tokens per question versus 16,910 for full history. Multi-hop F1 27.02 versus 25.02. Removing link generation and evolution drops multi-hop F1 to 9.65. DialSim F1 3.45 versus 2.55.
(b) "The system requires approximately 1,200 tokens per memory operation, achieving an 85-93% reduction in token usage compared to baseline methods"
(c) Section 4.3 Cost-Efficiency Analysis; Tables 1 to 3.

4. Limits the authors admit
(a) Note quality depends on the underlying LLM. Text only; multimodal is future work. Nothing on forgetting or drift.
(b) "the quality of these organizations may still be influenced by the inherent capabilities of the underlying language models."
(c) Section 6 Limitations.

5. (inferred) What Goals could take
- Keep decisions and evidence as small markdown notes with front matter (keywords, tags, context, links); a write hook asks the model to fill them using the Appendix B prompt.
- On each new note, grep or BM25 the top 5 to 10 old notes (no vectors needed), ask for links, write links both ways. The repo links one way.
- Evolve only derived fields (context, tags), never raw proof or decision text. Append each rewrite to a history list; the repo declares one but never fills it.
- After a reset or compaction, a hook injects top-k notes plus linked neighbours. The paper's k sweep plateaus near k=30 to 40.
- Add what the paper lacks: a read counter and last-used date bumped by a hook, to drive pruning.

## Code

Repo: https://github.com/WujiangXu/A-mem-sys

6. Repo facts: MIT license (LICENSE). Python. Folders: agentic_memory/, tests/, Figure/. README presents a usable library (pip install) and points to WujiangXu/AgenticMemory for the paper's experiments.

7. Where the logic lives
- agentic_memory/memory_system.py: MemoryNote, AgenticMemorySystem (add_note, analyze_content, process_memory for link plus evolution, search_agentic).
- agentic_memory/retrievers.py: ChromaRetriever, builds embedded text and runs vector search.
- agentic_memory/llm_controller.py: OpenAI, Ollama, SGLang, OpenRouter backends returning JSON.

- [agentic_memory/memory_system.py:69] <<self.links = links or []>>
- Vectors sit in an in-memory ChromaDB client with no disk path, and the system resets it on start, so notes vanish between runs unless saved: [agentic_memory/retrievers.py:26] <<self.client = chromadb.Client(Settings(allow_reset=True))>>

9. Prompts and policies
- One combined prompt decides links and evolution: [agentic_memory/memory_system.py:132] <<You are an AI memory evolution agent responsible for managing and evolving a knowledge base.>>
- Strengthen adds links to the new note only: [agentic_memory/memory_system.py:717] <<note.links.extend(suggest_connections)>>
- Neighbours are rewritten in place: [agentic_memory/memory_system.py:740] <<neighbor_memory.context = new_context_neighborhood[i]>>

10. Paper vs code
- Paper has two LLM calls (link Ps2, evolve Ps3); code makes one, in process_memory.
- Paper evolves context, keywords and tags; code updates neighbour tags and context only, in the Python dict. The vector index is rebuilt only every 100 evolutions: [agentic_memory/memory_system.py:288] <<if self.evo_cnt % self.evo_threshold == 0:>>
- Ps3 lists "merge" and "prune"; code handles only strengthen and update_neighbor.
- retrieval_count, last_accessed, evolution_history are stored but never updated.
- Default search() ignores links; search_agentic() adds them. Neighbour search uses k=5.
- Benchmark code and baselines are not in this repo.
