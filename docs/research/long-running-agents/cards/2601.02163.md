# 2601.02163: EverMemOS: A Self-Organizing Memory Operating System for Structured Long-Horizon Reasoning

## Paper

1. Problem and claim: (a) Long-term chat agents outgrow the context window; flat stores of isolated records retrieve fragments and miss conflicts. Claim: a three-phase lifecycle (MemCells, then MemScenes and profile, then sufficiency-checked retrieval) gives coherent long-horizon reasoning. (b) "the absence of an explicit mechanism to transform fragmented episodic experiences into coherent and stable knowledge structures" (c) Section 1, Introduction, page 2.

2. Mechanism: (a) LLM cuts dialogue at topic shifts into MemCells (episode, atomic facts, foresight with validity dates). Each cell joins the nearest scene by embedding similarity or starts one; profile updated from scene summaries. Read: hybrid search, rerank, sufficiency check, expired foresight dropped. (b) "produces a concise, third-person narrative with resolved coreferences, establishing a stable semantic anchor." (c) Section 3.3, page 4.

3. Evidence: (a) LoCoMo overall 93.05% (GPT-4.1-mini) versus Zep 85.22%; LongMemEval 83.00% versus MemOS 77.80%; PersonaMem-v2 53.25% with profile versus 43.93% episodes-only. Dropping MemScenes lowers LoCoMo to 89.16. (b) "outperforms the strongest baseline on each benchmark overall, i.e., Zep on LoCoMo by 7.0% and 9.2%, and MemOS on LongMemEval by 6.7%." (c) Section 4.2, page 6, Tables 1-2.

4. Limits: (a) Text-only benchmarks; extra LLM calls raise latency and cost versus single-pass baselines; no benchmark stresses ultra-long timelines; foresight and profile are shown only in qualitative cases. (b) "computational cost relative to single-pass baselines." (c) Limitations, pages 8-9.

5. (inferred) What Goals could take:
- A Stop or SessionEnd hook asks the model for one episode file: third-person narrative with resolved references, atomic facts, and foresight lines carrying a valid-until date. A SessionStart hook drops expired foresight.
- Keep a topic index file that groups episodes; rewrite the decisions or profile file from topic summaries, not raw turns.
- Add a prompt step before acting: 'is the recalled context enough? if not, rewrite the query', capped at two rounds.
- Weekly merge per topic, newest state wins, with originals soft-archived (a `deprecated_by` line), never deleted.

## Code

Repo: https://github.com/EverMind-AI/EverMemOS

6. Repo facts: Apache-2.0 `LICENSE`; Python 3.12+; folders `src`, `tests`, `benchmarks`, `docs`, `scripts`, `examples`, `use-cases`, `deploy`, `data`. README calls it EverOS, a local-first memory library and server; `benchmarks/` runs four benchmarks. Both library and experiments.

7. Where the logic lives:
- `src/everos/memory/extract/boundary/detection.py`: buffers messages, LLM picks episode ends, commits MemCells.
- `src/everos/memory/extract/pipeline/user_memory.py`: one episode extraction per cell, writes markdown, emits events.
- `src/everos/memory/strategies/trigger_profile_clustering.py`: online clustering of episodes (the paper's MemScenes).
- `src/everos/memory/strategies/extract_user_profile.py`: folds episodes into `user.md`.
- `src/everos/memory/reflection/orchestrator.py`: offline cluster merge, soft-deprecates originals.
- `src/everos/memory/search/agentic.py`: cluster-scoped fact search with sufficiency check.

8. Storage: Markdown daily logs per owner (`episodes/episode-<date>.md`, hidden atomic fact and foresight logs, `user.md`) are the truth. SQLite holds the message buffer, memcell rows and clusters. LanceDB vectors and BM25 are rebuilt from Markdown by a file watcher.

10. Paper vs code:
- "MemScene" is a `Cluster` in code (cosine 0.65, 7-day window; paper uses 0.70 or 0.50 with 7 or 30 days).
- Foresight extraction is off by default and no search route reads it. [src/everos/memory/strategies/extract_foresight.py:129] <<    enabled=False,>>
- Profile is built from episodes, not scene summaries. [src/everos/memory/strategies/extract_user_profile.py:180] <<        return await ProfileExtractor(llm=deps.llms.profile).aextract_from_episodes(>>
- Atomic facts and foresight are separate async files, not fields of one MemCell.
- Reflection (LLM merge, default off) is in code, not in the paper.
- Boundary detection is one batch call over the buffer by default, not a sliding window.
