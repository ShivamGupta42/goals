# 2308.10144: ExpeL: LLM Agents Are Experiential Learners

## Paper
1. Problem and claim: (a) Context windows leave agents with no memory across tasks, and Reflexion only improves within one task. Claim: an agent can learn across tasks, without weight updates, from stored text experience placed in the prompt. (b) "our approach emphasizes the importance of retaining experiences across multiple tasks" (c) Section 1, Introduction.

2. Mechanism: (a) Two text stores built after training: successful trajectories in a Faiss vector store (read by task similarity), and an insight list an LLM edits with ADD, EDIT, UPVOTE, DOWNVOTE; count zero deletes. Both go into the eval prompt. (b) "A newly added insight will have an initial importance count of two associated with it" (c) Section 4.2, Learning from Experiences.

3. Evidence: (a) ReAct to ExpeL success rate: HotpotQA 28% to 39%, ALFWorld 40% to 59%. WebShop reward 0.665 to 0.701. FEVER transfer from HotpotQA insights 63% to 70%. Reflections fed into insight extraction hurt (29% vs 39%). (b) "ExpeL consistently outperforms the baselines on all domains" (c) Figure 5 caption, Section 5.2; Tables 1, 3, 5.

4. Limits: (a) Text-only observations, closed API models, no theory behind prompting. Insights are kept whole in the prompt; truly lifelong agents would need retrieval over insights to bound context. (b) "might be needed for truly lifelong learning agents to ensure a manageable context window size" (c) Section 6, Conclusion and Limitations.

5. (inferred) Ideas for Goals:
- Keep a `lessons.md` of numbered rules, each with a count. At each phase end a prompt asks for at most 4 operations (AGREE, REMOVE, EDIT, ADD) against the list. A small hook applies counts (+2 new, +1 agree or edit, -1 remove, delete at 0). This gives forgetting with no database.
- When the list passes a size, switch the prompt to 'remove first, add only if very different' and make removals count triple (as the code does).
- Store each failed attempt beside the later success for the same task in the proof files; compare the pair at phase end.
- A session-start hook injects the rules file plus the top 3 past successful runs matched by task title, skipping examples over a token cap.
- Keep the model's own reflections out of rule extraction (paper: it hurt).
- Humans may edit the rules file; record provenance.

10. Paper vs code:
- Paper says UPVOTE and DOWNVOTE; code uses AGREE and REMOVE. No hard cap: 20 is a target, and full mode starts at max_num_rules+5.
- Code parses LLM output strictly and drops operations not ending in a period.
- Paper tests task and reason similarity; code also has step, thought, action, reflection, rotation and random strategies, rerankers, kNN or SVM retrievers.
- The transfer "finetune insights" prompt (Fig. 4) is not in the repo; FEVER has only a hand-written insight text.
- Config default llm is gpt-3.5-turbo; the paper's insight model is gpt-4-0613.
