# 2307.03172: Lost in the Middle: How Language Models Use Long Contexts

## Paper

1. Problem and claim: Long windows are not used evenly. Accuracy depends on where the relevant item sits: best at the start or end, worst in the middle, even for long-context models.
   Quote: "models are better at using relevant information that occurs at the very beginning (primacy bias) or end of its input context (recency bias)". Where: Figure 1 caption, page 1.

2. Mechanism: Not a memory system; nothing is stored or updated. It keeps the question and documents fixed, moves the one answer document to a chosen slot, and scores accuracy. A key-value task does the same with UUID pairs.
   Quote: "we adjust the order of the documents to change the position of the document that contains the answer". Where: Section 2.1.

3. Evidence: GPT-3.5-Turbo, 20 documents: 75.8% answer first, 53.8% at 10th, 63.2% last; closed-book is 56.1%. 16K and 100K versions match short ones. Going from 20 to 50 documents gains about 1.5%.
   Quote: "GPT-3.5-Turbo 75.8% 57.2% 53.8% 55.4% 63.2%". Where: Appendix G.2, Table 6 (positions 1, 5, 10, 15, 20).

4. Limits the authors admit: No limitations section. They admit greedy decoding only, GPT-4 on a subset because of cost, and that their explanations come from preliminary investigations and hypotheses.
   Quote: "We use greedy decoding when generating outputs and leave exploration of other decoding methods to future work." Where: Section 2.2.

5. (inferred) What Goals could take:
   - A hook puts the goal and current phase at the top of the injected bundle and repeats the next action and done-check at the very end (start and end are the strong slots).
   - Keep injected plan, decision and proof text short and ranked, newest and most relevant first, old items cut. Gains stop near 20 items.
   - After a reset, reload from the plan file; do not trust a big window.
   - Add a self-test: plant a known decision at different positions in the bundle, ask for it back, compare.
   - For exact lookups (a decision, a proof line) repeat the query before and after the data; it fixed key-value retrieval but not QA.

## Code

Repo: https://github.com/nelson-liu/lost-in-the-middle

6. Repo facts: MIT license (LICENSE). Python. Folders: src, scripts, tests, qa_data, kv_retrieval_data. README says it holds the paper's accompanying material: data, data-generation scripts, prompt templates and a small package. Experiments plus a small package, not a memory library.

7. Where the logic lives:
   - src/lost_in_the_middle/prompting.py: builds the QA and key-value prompts.
   - src/lost_in_the_middle/prompts/qa.prompt (and 5 variants): templates, including query-aware and random-order.
   - scripts/make_qa_data_from_retrieval_results.py: inserts the gold passage at a chosen index among distractors.
   - scripts/make_kv_retrieval_data.py: makes UUID key-value records.
   - scripts/get_kv_responses_from_mpt.py: moves the target pair to the chosen index, runs the model.
   - scripts/evaluate_qa_responses.py: scores by answer-substring match (metrics.py).

8. How it is stored: gzipped JSONL files, a frozen Document dataclass, ordered key-value lists.
   [src/lost_in_the_middle/prompting.py:14] <<class Document:>>
   [scripts/make_qa_data_from_retrieval_results.py:78] <<ctxs.insert(gold_index, gold_chunk)>>
   [scripts/make_kv_retrieval_data.py:44] <<example = {"ordered_kv_records": ordered_kv_records, "key": key, "value": value}>>

9. Prompts and policies: one fixed instruction, numbered documents, and scoring on the first output line only so a model cannot win by copying the context.
   [src/lost_in_the_middle/prompts/qa.prompt:1] <<Write a high-quality answer for the given question using only the provided search results (some of which might be irrelevant).>>
   [src/lost_in_the_middle/prompting.py:60] <<formatted_documents.append(f"Document [{document_index+1}](Title: {document.title}) {document.text}")>>
   [scripts/evaluate_qa_responses.py:62] <<model_answer = model_answer.split("\n")[0].strip()>>

10. Paper vs code: Run scripts exist only for MPT, LongChat and Llama-2 on local GPUs; none for GPT-3.5, Claude or GPT-4, which carry the main results. Also missing: Flan-T5 and Flan-UL2 runs, the open-domain retriever sweep (Section 5), random-document distractors (Appendix B) and the figures. Data is included, the full pipeline is not.
