# 2503.14499: Measuring AI Ability to Complete Long Software Tasks

## Paper

1. Problem and claim: Benchmark scores do not say how long a task an AI can finish. It proposes the 50% time horizon: the human task length an AI completes half the time. Main claim: this horizon doubles about every seven months.
   Quote: "Despite rapid progress on AI benchmarks, the real-world meaning of benchmark performance remains unclear." (Abstract, p. 1)

2. Mechanism: Memory: not stated. Its agent scaffolds use only simple context management. It measures the 50% time horizon: a logistic fit of model success against geometric-mean human time per task; the horizon is the length at 50%.
   Quote: "we fit time horizons by performing the following logistic regression" (Section 3.1, p. 5)

3. Evidence: GPT-2: 2 seconds. o3: 110 minutes. Doubling time: 207 days (95% CI 166-240), about 7 months, 2019-2025. A 2024-only fit gives about 3 months; the authors say that is not robust for extrapolation. The 80% horizon is 4-6x shorter.
   Quote: "time horizon has doubled every 207 days with a 95% bootstrapped" (Section 3.2, p. 6)

4. Limits: Results depend on the task suite, the baseliner's skill and context, and the domain. Messier real work may not follow the trend. The 2024-25 trend has low confidence: only seven models. Elicitation effort was limited.
   Quote: "caution that time horizon is always measured relative to a domain, task distribution, and human" (Section 6, Limitations and future work, p. 10)

5. (inferred) Goals cannot retrain the model, but the paper's failure counts point to plain-file and hook changes:
   - Repeat detector: repeating failed actions was the top GPT-4 failure (12 of 31). A PostToolUse hook can count identical failing commands and add a prompt to change approach or log a blocker.
   - Stop gate: premature abandonment was the top o1 failure (16 of 32). A Stop hook can block ending a phase while proof items are open, unless a blocker is written to the plan file.
   - Phase sizing: the 80% horizon is 4-6x shorter than the 50% one. A planning prompt can cap each phase near the length of past phases that passed proof, and hooks can append each phase's start and end time to a plain file so the user sees real run length over time.
