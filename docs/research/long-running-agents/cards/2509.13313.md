# 2509.13313: ReSum: Unlocking Long-Horizon Search Intelligence via Context Summarization

1. Problem and claim
- (a) Web agents need long exploration, but the context window fills and ReAct fails at the limit. Claim: periodic summarization of history into a compact summary allows unbounded exploration, training-free, with no architecture change.
- (b) "a fundamental conflict between the need for extensive exploration and the constraints of limited context windows"
- (c) Abstract, p.1

2. Mechanism
- (a) Text only. Written when context nears its limit: a summary tool writes a goal-oriented summary. History resets to (question, summary). Old thoughts and tool outputs are dropped. Agent weights change only in ReSum-GRPO.
- (b) "Summarization can be triggered systematically, e.g., hitting token limits, or autonomously by the agent."
- (c) Trigger and reset: Section 3.1, p.3. Summary keeps only facts stated in the conversation; uncertain facts are left out (Appendix C, p.14). Exact trigger threshold: Not stated. Summary tool is ReSumTool-30B, fine-tuned from Qwen3-30B-A3B-Thinking (Section 3.2, pp.3-4). Resume: the summary is joined to the question and the agent is asked whether it is enough (Appendix C, p.14).

3. Evidence
- (a) Training-free ReSum: +4.5% average gain over ReAct. ReSum-GRPO: +8.2% more. WebSailor-30B on BrowseComp: 12.8% ReAct vs 16.0% with ReSumTool-30B. Generic summarizer can fall below ReAct (Qwen3-30B, WebSailor-3B, BrowseComp-zh: 6.9% vs 8.2%).
- (b) "achieving average absolute gains of 4.5% over ReAct"
- (c) Section 4.2, Table 1, p.6; ReSum-GRPO in Table 2, p.7.

4. Limits the authors admit
- (a) Triggers are fixed rules, not agent-chosen, since self-initiated management often exceeds current agents. Future work: agent-driven triggers and quality control so long-range dependencies survive summaries. ReSum-GRPO adds about 33% to 69% training time, which they call manageable.
- (b) "reliable self-initiated context management often exceeds the capabilities of current agents"
- (c) Section 3.1, p.3; future work in Section 5, p.8; training cost in Section 4.3, p.8 and Appendix F.1, p.18.

5. (inferred) What a harness like Goals could take
- Keep memory in files, not chat. ReSum's summary lasts only for one run, and ReSum has no memory across tasks. Goals' plan, proof and decision files can hold what ReSum drops.
- When context is large, write a handoff file: the question, then an Essential Information section with only certain, sourced facts. A PreCompact hook can trigger the write before Claude Code compacts.
- On resume, the agent reads the handoff first and judges whether it is enough before searching again. This is a prompt rule, not code.
- Count tool calls with a PostToolUse hook (the paper caps runs at 60 calls). At the cap, mark the run failed in the proof file and request a summary.
